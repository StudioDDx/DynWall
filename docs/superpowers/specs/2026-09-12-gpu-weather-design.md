# GPU weather wallpaper — approved design

Approved in chat September 12, 2026. Target: GNOME Shell 50 / Wayland, NVIDIA Quadro M6000. Keep the existing Python-rendered sky as fallback; do not animate by repeatedly changing picture-uri. English-only artifacts.

TopWeather remains the weather authority. On successful refresh it exports an atomic, private snapshot at `$XDG_CACHE_HOME/topweather/current.json` (default `~/.cache/topweather/current.json`). Extend both providers with numeric cloud coverage, wind direction, precipitation data and coordinates where available. Missing measurements remain null, never invented measurements. Convert to canonical units. Snapshot envelope: `{schemaVersion:1, fetchedAt:<epoch milliseconds>, provider, location, unit, latitude:<number|null>, longitude:<number|null>, current:{...existing fields, cloudCover:<0..100|null>, precipitation:<mm/hour|null>, rain:<mm/hour|null>, snowfall:<mm/hour water equivalent|null>, windSpeedKmh:<number|null>, windDirection:<degrees|null>, weatherCode:<number|string|null>}}`. Provider period differences and snowfall units must be explicit; snowfall may remain null if conversion unsupported. Location/provider changes invalidate old snapshot. Export contains no credentials.

Dynwall writes `$XDG_CACHE_HOME/dynwall/scene.json`: `{schemaVersion:1, generatedAt:<epoch milliseconds>, spec:<existing sky spec>, weather:<snapshot|null>, renderer:{enabled:<bool>, fps:<15..60>, quality:<low|balanced|high>}}`. Preserve existing art direction/palette but observed weather drives cloud/precipitation. Controller helpers are pure/testable; snapshot expires after 2 hours, unreasonable future times rejected. Missing data means unknown, not fabricated live weather.

A GNOME extension `dynwall@rucaradio` attaches a noninteractive actor behind windows and desktop icons, with native GPU shaders (confirmed installed Shell.GLSLEffect interface). It reads scene plus TopWeather snapshots, refreshes independently of weather network calls, smoothly interpolates conditions, renders clouds/rain/snow/night stars with cloud occlusion. Initial target 30 FPS with low/balanced/high quality. Lock, suspend, reduced motion and disabled rendering stop scheduling. Disable tears down actors/timers/monitors and exposes original static wallpaper. No compositor changes until isolated rendering validation passes. Multi-monitor coordinates stay continuous.

Validation: TDD for provider normalization, snapshot validation and renderer state; compile/render actual GLSL offscreen and inspect day/overcast/rain/night captures; then narrow GNOME integration. Existing tests must still pass. No claim of lock/hotplug/performance correctness without runtime evidence. Keep rollback and document live activation boundaries.
